2 系统关键技术
本章节主要是对“咖啡商城”系统在开发过程中所使用的主要相关技术展开介绍，其中包括系统的 B/S 架构、后端的 SpringBoot 框架与 MyBatis 持久层技术、前端的 Thymeleaf 模板引擎技术、底层的 MySQL 数据库，以及项目构建所依赖的开发环境等方面。

2.1 系统架构选择
在进行“咖啡商城”的系统开发前，首先需要确定平台整体的网络运行架构。目前主流的软件架构主要分为 C/S（Client/Server，客户端/服务器）和 B/S（Browser/Server，浏览器/服务器）两种。考虑到电子商务平台需要面向广大的普通消费者，要求系统具备良好的易用性和跨平台访问能力，因此本项目采用了 B/S 架构进行开发。

B/S 架构是一种随着互联网技术的兴起而发展起来的网络结构模式。在这种架构体系下，系统的用户界面完全通过标准的 Web 浏览器来实现。前端主要负责页面的视觉展示与部分基础的交互逻辑，而核心的业务逻辑处理、事务控制以及数据存储，则部署在后端的服务器上。

图2-1 B/S模式网络架构图

对于本商城系统而言，采用 B/S 架构的特点主要体现在以下几个方面：
（1）降低用户使用门槛：采用 B/S 架构意味着不需要额外部署客户端。消费者无需下载和安装专门的应用程序，只要有一台能够连接互联网且装有主流浏览器的设备，即可访问“咖啡商城”进行浏览与购物。
（2）便于系统维护与升级：对于系统管理员和开发者而言，当商城需要进行功能迭代或修复缺陷时，所有的代码更新和数据库调整工作仅需在服务器端完成。客户端浏览器在下次访问时会自动获取到最新版本的页面与服务，这降低了后期的运维成本。
（3）跨平台兼容性：B/S 架构依赖于标准化的 HTTP/HTTPS 协议与 Web 标准，具备基础的跨平台特性，能够兼容 Windows、macOS 以及各类移动端操作系统。

在本项目中，B/S 架构配合后端的 SpringBoot 框架和前端的 Thymeleaf 模板引擎，构建了一个基础的数据安全且交互清晰的在线咖啡销售环境。

2.2 关键性开发技术
2.2.1 SpringBoot框架
SpringBoot 作为构建 Java 应用的常见框架，秉持“约定大于配置”的核心思想，简化了应用程序的初始化和部署流程。它通过集成嵌入式服务器（如 Tomcat），让开发者能够直接以 JAR 包形式运行整个应用，减少了对外部环境的复杂依赖。

相关在线测试系统的研究中也利用了该框架易于部署的特性快速搭建应用[18]。同时，SpringBoot 生态在构建在线购物 Web 应用后端时具备一定优势，其内部集成的自动配置机制是提升开发效率的重要方式[19]。本项目基于 SpringBoot 的这些特性，确保咖啡商城系统在简化配置的同时，能够实现稳定的运行。

2.2.2 Thymeleaf 模板引擎
Thymeleaf 是一种服务器端 Java 模板引擎，专门为 Web 环境设计。与传统的 JSP 不同，Thymeleaf 支持 HTML 原型，即在没有后端支持的情况下，模板文件也能在浏览器中正常显示静态内容。这一特性便利了前后端分离的开发模式，使得开发者可以直观地调试页面布局。在本项目中，Thymeleaf 与 SpringBoot 结合，负责将后端的数据动态渲染到前端页面上，为用户提供基础的界面展现，这也为电商相关场景的有效适配提供了前端组件支撑[20]。

2.2.3 MyBatis 持久层框架
MyBatis 是一个基于 Java 的持久层框架，它内部封装了 JDBC，使开发者只需关注 SQL 语句本身，而无需处理加载驱动、创建连接等繁杂的过程。MyBatis 通过 XML 的方式将要执行的 SQL 语句配置起来，并通过 Java 对象和 SQL 的动态参数进行映射生成最终执行的语句。在咖啡商城中，MyBatis 负责处理底层的数据库操作，如商品的多条件搜索、订单的查询等，并在数据持久化方面提供了规范的映射纽带以保证访问的有效性[21]。

2.2.4 MySQL 数据库
MySQL 是一款基于 SQL 的开源关系型数据库管理系统，在常规的 Web 应用领域得到了广泛应用。其特点在于将数据结构化存储与查询能力融合。在项目中，MySQL 被用于存储用户、商品、订单等关键业务数据。通过设计单体架构下的表结构，确保了业务数据交互的查询性能，并巩固了底层数据防线[22]。

2.2.5 大语言模型接口应用
在系统前台界面中，接入了基于大语言模型（LLM）的 AI 客服功能。通过调用 DeepSeek 与 Gemini 的应用程序接口（API），开发了一个简单的智能对话模块，支持上下文对话记忆。技术实现上，主要通过在后端封装提示词（Prompt）来引导模型输出咖啡风味建议与选购指南，提升了用户挑选商品时的互动感。逻辑层主要负责处理异步请求与异常状态，保证了调用外部大模型服务时的响应速度与交互稳定性。

2.3 基于协同过滤的商品推荐算法
本系统首页的商品展示区域除了常规的分类展示外，为了提升用户的选购体验，简单接入了基于物品的协同过滤（Item-based CF）推荐算法。考虑到系统作为本科毕业设计的实际数据量和单体架构的复杂度，商城并未引入庞大的独立算法模型库，而是采用了基于 Java 内存运算结合数据库查询的基础方法来进行商品推流。

在具体实现上，系统首先通过业务逻辑层提取用户对不同咖啡商品的交互行为（如购买、评价、收藏），并根据行为权重将其量化为评分矩阵。随后，利用余弦相似度公式计算商品之间的特征关联度，构建系统的推荐映射模型[23]。当用户访问首页时，推荐模块会根据用户历史的消费与反馈记录，在内存中动态匹配出与其偏好相似度最高的商品集合，并过滤掉已购买的商品，最终生成个性化的推荐列表返回给前端。

2.4 开发工具及环境
在项目中，Navicat 主要用于 MySQL 数据库的表结构设计与维护、测试数据的批量导入与验证，同时借助其可视化查询界面，快速执行 SQL 语句、排查数据异常，为系统的数据层开发与测试提供了高效支撑。

系统开发基于 Java 与 Spring Boot 框架，IntelliJ IDEA 为项目提供了完整的开发支撑：一方面通过自动依赖管理、热部署功能提升了开发效率；另一方面通过代码规范检查、调试工具保障了代码质量，是开发过程中的核心工具。

系统的运行环境架构在 Windows 10 操作系统之上，后端业务逻辑基于 JDK 1.8 语言环境进行编译与执行。在数据存储方面，采用 MySQL 5.7 关系型数据库负责买家账号、咖啡商品信息及交易订单等核心数据的结构化存储。此外，项目通过 Maven 工具实现对工程依赖的统一拉取与版本管控，确保了开发、编译与部署过程中技术栈的一致性。
