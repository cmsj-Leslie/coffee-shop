 4 系统详细设计
4.1 系统概要设计
咖咖商城是一个采用 B/S（Browser/Server，浏览器/服务器）架构的电子商务项目。本系统主要分为管理员和普通用户两个角色。其中，普通用户可以进行商城主页浏览、商品搜索、购物车管理、订单支付模拟、AI 智能咨询以及商品评价等功能；管理员则可以实现商品发布与上下架、分类管理、订单发货处理、系统用户管理及评价数据审核等功能。本系统的功能结构如图4-1 所示。 
 
图4-1 系统功能结构图
4.1.1 登录模块设计
本系统基于 B/S 模式，后端代码采用了标准的“三层架构”开发模式，将业务处理划分为三个层次：表示层、业务层和数据层。这样设计能降低各功能模块的耦合度，方便代码维护。
表示层：主要负责和用户交互。前端页面使用 HTML 和 Bootstrap 编写，利用 Thymeleaf 引擎渲染商品等动态数据。用户的点击、加入购物车等操作，会发送到后端的 Controller 控制器。
业务层：负责处理核心业务逻辑。Controller 收到请求后，转交给 Spring Boot 管理的 Service 层。比如用户提交订单时，计算总金额、校验商品库存等核心代码，都在这里完成。
数据层：负责和 MySQL 数据库交互，执行增删改查。本项目使用了 MyBatis 框架，通过配置 Mapper 接口和 XML 映射文件，把 Java 对象直接映射到数据库的表中，提升了查询以及开发的效率。

4.2 功能模块设计
4.2.1 登录模块设计
本系统的用户登录功能涵盖了前台用户登录与后台管理员登录。用户在登录界面中输入正确格式的邮箱（账号）和密码后，点击登录按钮触发验证功能。系统将输入的信息与数据库 user 表中对应的数据进行比对。如果信息不匹配，系统会给出登录失败或账号密码错误的提示；信息匹配成功且角色权限核对无误，则成功登录并跳转至相应的主页或后台控制台。系统登录模块流程如图4-2 所示。
 
图4-2 登录流程图

4.2.2 商品管理模块设计
该模块的功能需要由管理员角色登录后台进行操作。管理员可以通过“发布商品”操作来实现商品信息的新增功能，并调用阿里云 OSS 接口上传商品图片。通过“修改”操作可对商品信息（如价格、库存、描述等）进行编辑和更新。在商品管理列表中，管理员可以使用“上架/下架”或“删除”功能来控制商品的展示状态。商品管理模块流程如图4-3 所示。

4.2.3 购物车与订单模块设计
登录成功后，用户可以在前台界面将心仪的咖啡商品加入购物车。用户在购物车页面勾选需要结算的商品并确认提交后，系统会跳转至订单创建页面。选择收货地址并确认支付后，系统后台将遍历选中的商品列表，执行库存扣减操作，并生成独立的订单记录。Pleskach V 等（2024）在特色电商系统中强调了购物车与订单流转的严密性对于保障电商交易底线的重要性[22]。本系统在订单生成环节正是基于此原则加入了完整的并发处理。购物车与订单模块流程如图4-4 所示。

4.3 数据库设计
在着手咖咖商城的数据库设计前，必须全面且深入地分析和理解本系统的各种业务需求，这涵盖了对交易数据流程、系统功能以及数据映射关系的了解。通过对需求的细致剖析，能够明确数据库中需要存储的数据之间的关联及数据类型。在此基础上确立了多个核心数据表，包括用户信息表、商品信息表、订单信息表、购物车表和AI聊天记录表等。这些数据库表的设计为系统的各项功能提供了坚实的数据支撑。

4.3.2 数据库表设计
数据库表设计在系统开发中占据核心地位，它关乎到业务数据的存储形式与组织结构。一个精心设计的数据库表可以在显著提升查询性能的同时，减少数据不一致现象和数据冗余。在实体间的数据关联机制上，本系统借鉴了 Guo T 等（2024）在互动共享平台中的映射纽带设计原则，采用标准的关系模型予以固化，保障了全局数据的参照完整性与业务一致性[23]。本系统的核心数据库表结构设计如下：
