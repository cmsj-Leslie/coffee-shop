### 2 系统关键技术

本章主要介绍“咖咖商城”系统开发过程中采用的核心技术与底层架构，具体包括系统的 B/S 网络架构、后端的 SpringBoot 框架与 MyBatis 持久层技术、基于 Thymeleaf 引擎的前端页面渲染技术、MySQL 数据库，以及项目部署与构建所依赖的基础运行与调试环境。

#### 2.1 系统架构选择

在进行系统代码编写前，首先需要确立整体的网络通信架构。当前主流的软件体系主要分为 C/S（客户端/服务端）与 B/S（浏览器/服务端）两种模式。考虑到电子商务类应用需要面向广泛的普通消费者，对系统的易用性和跨平台访问约束存在较高要求，因此本项目最终采用 B/S 架构进行开发。

B/S 架构是在 Web 互联网技术基础上发展起来的网络结构模式。在该架构下，系统的用户视图层完全通过标准的 Web 浏览器呈现。前端主要负责页面的静态渲染与常规的交互拦截；而核心的业务处理、并发控制与海量数据的存储，则统一集中交由后端物理服务器进行调度。

对于本系统而言，应用 B/S 架构具有以下实际优势：
（1）降低用户使用门槛：采用“零客户端”部署策略。消费者无需下载特定的应用安装包，只要拥有一台能够连接网络的主流设备（如电脑、平板），即可直接访问“咖咖商城”进行商品选购，从而扩大了平台的受众覆盖面积。
（2）简化系统维护流程：针对商城功能迭代、促销活动上线或程序缺陷修复，所有的代码打包和结构调整工作均集中在服务端完成。当客户端重新发起页面访问时，浏览器会自动加载最新的业务资源。这改变了传统软件依赖本地分发升级包的维护模式，降低了后期的系统运维复杂度。
（3）良好的跨平台兼容性：B/S 架构依赖规范化的 HTTP/HTTPS 协议与 Web 规范，天生具备跨平台运行能力，能够直接兼容 Windows、macOS 以及各类移动端操作系统，确保多设备访问时数据视图展现的一致性。

本系统以 B/S 架构为基础，配合 SpringBoot 服务端框架和 Thymeleaf 引擎，搭建了一个响应迅速、数据同步的在线咖啡销售环境。

#### 2.2 关键性开发技术

**2.2.1 SpringBoot框架**
SpringBoot 作为当前 Java 企业应用开发的主流框架，秉承“约定优于配置”的设计原则，有效简化了工程的初始化与打包流程。该框架通过将其内置的 Tomcat 等 Web 容器一并打包到应用中，支持开发者直接以独立的 JAR 包形式启动项目，减少了对外部服务器环境的繁琐维护依赖。

相关的诸如在线测试评估系统的验证与研发实践均表明，利用该框架易于部署的底层特性，能够快速搭建起具备横向扩展能力的应用后台接口支持 [18]。同时，SpringBoot 组件内部集成的自动装配机制，是处理类似于在线购物等 Web 应用后端高并发结账请求及服务交互交互的核心技术支撑 [19]。本项目引入 SpringBoot，主要是为了在保证业务代码轻量化的前提下，进一步稳定商城系统面对访客浏览的后端业务调度能力。

**2.2.2 Thymeleaf 模板引擎**
Thymeleaf 是一种专门用于 Web 和独立环境的 Java 服务器模板引擎。与传统的 JSP 页面不同，Thymeleaf 支持直接解析 HTML 原型，这意味着在脱离后端运行容器时，模板文件依然能够作为静态 HTML 直接在浏览器里正常渲染。这一机制有利于前后端分离模式下的界面布局与样式联调。在“咖咖商城”中，Thymeleaf 引擎与 SpringBoot 底层紧密对接，主要负责接收控制层传输的模型对象并动态显示至前端页面上，保障用户获得直观的数据反馈。

**2.2.3 MyBatis 持久层框架**
MyBatis 是一个基于 Java 的轻量级持久层框架。它对底层 JDBC 流的繁琐调用进行了封装，使开发人员能够将精力集中于业务关联的 SQL 逻辑编写上，而无需手动管理驱动注册和连接捕获。MyBatis 允许使用传统的 XML 文件或代码注解方式，将接口方法与 SQL 语句绑定，并通过动态标签完成参数的自动注入机制。在处理诸如商品多条件筛选、订单多表关联查询等复杂持久层操作时，MyBatis 保证了数据库检索的执行效率。

**2.2.4 MySQL 数据库**
MySQL 是一款成熟的开源关系型数据库管理系统。由于其适配性强、对服务器硬件要求低，在常规的中小型互联网应用领域中被广泛使用。在本项目中，选用 MySQL 作为系统的数据持久化仓库，负责存储用户账户记录、商品类目字典、订单明细等核心业务表。项目中通过合理设置主键索引和关联约束，确保系统在执行高频的业务读写操作时，具备良好的响应速度与引用完整性。

#### 2.3 核心业务算法与调度机制

本系统在底层实现上不仅依赖框架的基础连通封装，更在数据推流与促销结算环节引入了完备的引擎级计算策略，这也是整个商业级 B/S 系统严谨性与健壮性的核心体现。

**2.3.1 基于物品的协同过滤推荐算法（Item-based CF）**
为了提升消费者的购物体验与转化率，本商城系统在首页商品推流设计中摒弃了单纯的低效固定排序，引入了前沿且基于用户行为链路的物品协同过滤（Item-based CF）推荐算法。该算法的底层核心思想是通过分析全体用户的历史交互行为来提炼商品间的隐式关联相似度，进而将与目标用户以往偏好特征高度相似的其他关联商品过滤并推荐给用户。
在本系统的工程实现中，服务端首先在核心业务层构建全量的“用户-商品”交互稀疏评分特征矩阵。矩阵的特征值抓取逻辑及权重被设定为：高频强意愿的实际购买记为最高 3 分，中度意愿收藏动作记为 2 分，而星级评价则按用户打出的 1~5 对应真实星数转化为浮点权重提取。当同一用户对单一商品发生多种混合交互时取极值作为矩阵单点。最终，算法引擎通过核心遍历计算商品特征向量间的余弦相似度矩阵系数，并结合目标用户已交互清单的关联度进行加权求和，推导出全量候选项的推荐分。在物理剔除用户已购买商品（即兴趣拦截池）后，精准截取 Top-8 的商品集合向前端输出动态瀑布流。此外，对于缺乏任何历史行为轨迹的“冷启动”全新注册用户，平台路由则自动降级为全局高销量人气排序降维返回，确保了推流通道的可用性红线。

**2.3.2 基于后端的优惠券计算引擎防线**
立体的促销抵扣方案是当代电子商务引流成单不可或缺的基石。为此，本系统独立构筑了一套轻量防穿透的优惠券（Coupon）结算引擎流转规则。系统在底层 Service 源码域中严谨区分并通过策略拦截实现了满减券（Type=1，具备最低门槛 MinAmount 与固定削减额度）与固定打折券（Type=2，具备百分比 Discount 乘积折让）两类核心运算分支。
当终端消费者在订单结算锚点投递特定优惠券凭证标识时，后端拦截器首先在数据库检索比对该券种的全局状态是否处于绝对的有效期内（即当前系统时间介于 startTime 与 endTime 区间之间）。随后引擎拉取该券携带的限制参数，并重新核算购物车内部的待付累计基数，判定其是否达到“最低激活使用门槛”。这一系列的边界碰撞与精度缩放运算完全被深度嵌套于 Java 反射或后端核心事务逻辑域中强行执行。这种设计模型坚决杜绝了因依赖浏览器前端进行金额数值加减换算而可能遭到抓包篡改的逻辑穿透隐患，这也是符合典型中大型 B/S 系统财务模块数据绝对安全的底层工程建设规范。

#### 2.4 开发工具及环境

**2.4.1 Navicat简介**
Navicat 是一款常用的数据库操作客户端，提供标准的图形用户界面。它支持数据库记录的读写同步、本地备份以及日常的 SQL 测试功能。在本项目开发的初期与数据库维护周期中，Navicat 主要被用于实体表结构的可视化创建以及测试数据的模拟生成，有效降低了持久层维护的测试难度。

**2.4.2 IntelliJ IDEA简介**
IntelliJ IDEA 是一款主流的企业级集成开发环境（IDE）。它支持代码提示补全、依赖冲突检测以及断点跟踪等功能，且内置了对 Spring 体系与 Maven 工程库的对接支持。本系统主要采用 Java 语言进行后端程序的编写构架，依托该 IDE 的代码索引与静态排错机制，缩短了项目组件的开发和调试周期。

**2.4.3 运行环境**
（1）操作系统：系统开发与本地测试部署均在 Windows 系统环境下进行，为项目编译及组件配置提供底层支持。
（2）开发语言环境：采用 JDK 1.8 版本的 Java 语言环境，负责支撑系统后端的业务逻辑编译以及 JDK 8 新增的 Stream 聚合操作的算力开销。
（3）数据库环境：部署本地 MySQL 5.7 关系数据库服务，负责实现本系统所有的基础实体信息（包括买家账号、咖啡 SKU 数据及交易记录流等）的结构化存储。
（4）依赖管理工具：采用 Maven 统一管理项目的依赖体系结构。项目所需的内部框架支持以及第三方工具库包（如 Spring Boot 主干依赖项），均交由 Maven 脚本进行版本控制和工程打包构建。
