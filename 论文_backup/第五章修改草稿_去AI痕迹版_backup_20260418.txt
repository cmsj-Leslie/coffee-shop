5 系统功能实现

本章主要展示“咖啡商城”系统完成编码后的功能表现形态。按照项目既定的体系架构，本系统主要展示了持久层的代码实现、前台用户的交互页面，以及后台管理员的操作页面，并附有各模块的功能截图。

5.1 系统实现
本系统基于标准的 B/S 单体架构进行开发，所有的业务逻辑和数据处理都由服务器端统一完成。

5.1.1 系统结构
商城的页面展示与数据交互主要通过 HTTP 协议来实现。前端使用 Thymeleaf 引擎来渲染动态数据，响应用户的操作。后端的处理流程由 SpringBoot 框架进行管理，控制层（Controller）负责接收前端传来的参数，并在校验后将请求转发给业务逻辑层进行处理。这种分层方式符合基础的 MVC 开发规范。

5.1.2 数据持久层实现
在系统底层的数据库交互层面，数据存储在 MySQL 数据库中。通过引入 MyBatis 持久层框架，系统利用 XML 映射文件来编写 SQL 语句，这种方式比原生的 JDBC 编写起来更方便。所有的增删改查操作都通过 SQL 映射为 Java 对象。在处理“提交订单扣减库存”等关键操作时，系统在 Service 层的方法上添加了 @Transactional 事务注解，如果库存不足或出现报错，系统会自动回滚，防止出现超卖的情况。

5.2 用户端主要页面
系统前台主要为普通消费者提供选购和结算的功能，整体设计力求简洁直观。

5.2.1 前台首页与商品详情页面
商城首页为用户提供了最新上架商品、热门推荐及折扣商品的聚合展示。其中，热门推荐板块底层接入了基于物品的协同过滤（Item-based CF）算法，能够根据登录用户的历史行为进行动态的个性化展示。用户可以通过顶部导航栏进行分类筛选，或使用搜索框进行关键词检索。点击商品图片可进入详情页，查看咖啡的产地、风味描述及其他用户的评价。该系统功能实现效果如图5-1所示。

5.2.3 购物车与支付页面
用户可将心仪商品添加至购物车，支持修改数量或单项删除，并可选择账户内的有效优惠券参与抵扣。在结算支付环节，后端为了防止高并发下出现库存超卖，在核心 Service 提交方法上添加了 @Transactional 事务注解。系统会先核验优惠券有效性并判断可用库存，全部通过后再落库执行物理库存扣减、新增订单记录并清理购物车。如果中间有任意环节发生异常，系统均会自动触发事务回滚，确保交易数据的安全性。该核心业务实现效果如图5-4所示。

5.3 管理员端主要页面
管理员端是商城的后台管理区域，页面设计比较直观，主要用于商品和订单的日常维护。

5.3.1 系统注册登录页面
登录页面是系统各类角色的统一入口。管理员或普通用户在登录界面输入邮箱账号和密码后，后端会到数据库中进行信息比对。如果验证通过，系统会根据用户权限记录相应的 Session 信息。系统的登录界面如图5-9所示。

图5-9 登录页面图
